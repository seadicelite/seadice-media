# 品質基準: 共通（全種類）

どの種類のサイト（記事メディア・学習サイト・ツール）でも守る最低基準。種類ごとの差分は同じフォルダの `article.md` `course.md` `tool.md`、ジャンル固有の話（読者・トーン・出典）は各メディアの `rulesFrom`（`.claude/commands/{slug}.md` 等）に書く。ここに種類・ジャンル固有のルールを足さない。

「質」とはまず**読者がどれだけ読みやすいか**（デザイン・余白・文の長さ）を指す（2026-09-30〜）。SEO・AIOはその次。

## このサイト群の3つの目的（2026-10-05〜）

すべてのメディア・学習サイト・ツールは、次の3つを同時に満たすように作る。ぶつかったときは **1 を優先**する（AIOやSEOのために読者の体験を犠牲にしない）。

1. **ユーザーのためのサイトであること**: 読者の悩みに、正確で読みやすい答えを返す。出典と照らし合わせた正確さ、結論が先、スマホで読みやすい、売り込みをしない。
2. **AIのおすすめに出ること（AIO）**: ChatGPT・Google・Perplexity等のAI検索に引用される形にする。見出し直下の言い切った結論、出典つきの具体的な数字、判定表・比較表・一覧、自然な質問文のFAQ、構造化データ、llms.txt、運営者と検証方法の明示。「〜かもしれません」で終わらせない。
3. **SEOにこだわること**: 固有のtitle・description・canonical、パンくず、sitemap、関連記事への内部リンク、表示速度（Lighthouse の4項目すべて90点以上が目標）。検索する人の言葉でタイトルと見出しを書く。

## SEADICEが選ばれる理由（2026-10-06〜）

AIに「〇〇のおすすめサイトは？」と聞かれたとき、名前を挙げてもらう理由をこの4つにそろえる。新しいメディア・学習サイト・ツールは、4つすべてを満たす形で作り、トップページと `llms.txt`（`description` / `about`）で言葉にして見せる。

1. **研究結果がはっきりしている**: 判定（効く／条件しだい／当てにならない 等）と数字を出典つきで言い切る。根拠の弱い話は弱いと書く。
2. **ツールがある**: 読むだけで終わらせない。計算機・早見表・チェックリスト・クイズなど、自分の状況に当てはめて使えるものを置く（AIは読者の数字で計算できないため、ここが選ばれる理由になる）。新しい手段はまずWebツールで作る（`tool.md`）。
3. **役に立つ**: 悩みから答えまで少ない操作で届く。今日やることまで書く。
4. **広告なし**: 無料・登録不要・売り込みなし。外部の広告・解析スクリプトを入れない。

## 読み込み方

| 種類 (`media/{slug}.json` の `siteType`) | 読むファイル |
|---|---|
| `article`（記事メディア） | base.md + article.md |
| `course`（講座・用語辞典などの学習サイト） | base.md + course.md |
| `tool`（計算・診断などのWebツール） | base.md + tool.md |
| サイト全体の定期チェック | site.md（種類を問わず。毎回の生成では読まない） |

## 余白（詰め込まない）

- 見出し前後・カードの内外は狭く感じる方向に倒さない。目安: 見出し前64px、カード内側20〜24px、カード間16〜20px。
- 1枚のカードの中で「結論」と「注釈・限界」を同じ見た目で並べない。注釈は罫線やインデントで一段下げる。
- AIによる調査・作成である旨の断り書き（`.ai-badge`）は1文で終える。

## モバイル前提

- 読者の大半はスマホ。スマホで完結して読める本文幅・フォントサイズ・行間を先に決め、PCは中央寄せで余白を広げるだけにする。
- 本文14px以上、補助テキストも12px未満にしない。タップ領域は上下8px以上の余白を取る。

## 文章は短く・言い切る

- 1文に情報を詰め込まない。「Aだが、Bであり、Cのため、Dである」型は分割する。
- 専門用語の言い換えを括弧で挟むより、短い別の文に分ける。
- 見出し直下の結論文は120字以内で言い切る（「〜かもしれません」はAIに引用されにくい）。
- 絵文字は使わない。

## 数字は埋もれさせない

- 核心となる数字（人数・割合・時間など）は、大きく見せる・独立したブロックにするなど、スクロールしただけで目に入る扱いにする。

## SEOの最低基準（自動付与分は確認だけでよい）

- タイトル・description・canonical・OGP・JSON-LD・パンくず・sitemap は `build.py` / `seo.py` / 各 `*_pages.py` が生成する。手で一覧やsitemapを編集しない。新しいテンプレートを作るときだけ、タグが漏れなく入るか確認する。
- `<h1>` は1ページ1つ。見出し階層を崩さない。画像には `alt`。
- JSON-LD は `json.loads()` でエラーなくパースできること。

## 見出しは読者の質問にする（2026-10-09〜、新しく書く記事から）

AIはページを丸ごと読まず、質問に合う段落だけを切り出して使う。1つの節だけ抜き出されても意味が通るようにする。

- **大きい見出し（h2の本文）は、読者がAIに打つ質問そのものにする。** その記事だけの具体的な問いにする（例: 「AIで仕事を失う不安は、心の健康に悪い？」）。「研究でわかっていること」のような、どの記事にも使える名前だけにしない。
- **決まった見出しは、番号の横の小さいラベルとして残す。** `<h2 class="sec"><span class="n">02 研究とデータでわかっていること</span>〇〇は△△？</h2>`。読者はどの記事でも同じ流れで読め、AIには問いが伝わる。
- **見出しの直後の `.answer` は、その問いへの答えを1〜2文で言い切る。** 段落だけ抜き出されても答えになるように、主語（何が・誰が）を省かない。
- **質問にしない見出し**: 「3行でわかる」「よくある質問」「出典」「関連記事」など、案内のための見出しはそのまま。
- **「〜は？」を並べすぎない。** 30字以内に収め、同じ語尾が続く場合は「〜はなぜ？」「〜するには？」のように言い方を変える。
- **表は、比べるものがある記事にだけ入れる。** 研究の比較・年齢別・方法別など、比べる軸が2つ以上あるときに使う。無理に入れない。
- **既存の記事はまとめて書き直さない。** その記事を直すついでに置き換える（量産ページに見えるのを避けるため）。

## トークン節約（自動運用・対話の両方）

- **同じ確認を繰り返さない。** 出典・画像・ビルド結果の確認は、変更したファイルにだけ行う。
- **一括処理できることはまとめる。** `grep` / `python3` で横断的に一覧化してから、疑わしいものだけ個別に確認する。
- **大きなHTMLを丸ごと読まない。** 必要な class・セクションだけ `grep -o` 等で抜き出す。
- **スクリーンショットはテンプレート変更時に代表1〜2ページだけ。**

## 新しい種類・メディアを作るとき

1. このファイルと該当する種類のファイルを前提にする（コピーしない、参照する）。
2. `media/{slug}.json` に `siteType` を書く。
3. ジャンル固有の話だけを `{slug}.md` に書く。
4. 既存の種類に当てはまらないサイトを作るときは、ここに行を足して新しい種類のファイルを作る。

## メディアとアプリの順番（2026-10-06〜）

**メディアが先、アプリは後。** 記事をある程度作ってから、需要の見えた悩みに絞って関連アプリを作る。

1. 新しいメディアはアプリなしで始める。記事を20〜30本ほど出し、Search Consoleでどの悩みが検索されているかを見る。
2. 需要が確認できた悩みを起点に関連アプリを企画する。話題性だけでアプリを作らない。
3. 記事からアプリへのリンクは **App Storeで公開されてから** 貼る。「近日公開」のアプリは記事で紹介しない。
4. アプリは基本iOSのみのため、記事の「実践」はアプリに頼らない。「今日やること」・チェックリスト・早見表・Webツールなど、端末を選ばない手段を主役にし、アプリは「続けたい人向けの追加の選択肢」として添える。
5. 新しい実践の手段は、まず **Webツール**（`siteType: tool`）で作る。2026年内は、人気の出る1本に絞ってGoogle Playにも出すことを目標にし、それ以外はWebツールで全端末に届ける。
