# 品質基準: サイト全体の定期チェック

記事・レッスン1本ごとの基準ではなく、**メディア1つ全体**を見るチェック。毎回の記事生成では読まない（トークン節約）。

## いつやるか

- メディアごとに月1回、または記事数が50・100・150…に達したとき。
- 新しいメディアを公開する前に1回。

## 1. 量産判定の回避（最優先）

毎日自動生成しているメディアは、Google の「大量生成コンテンツの不正使用」ポリシーに最も触れやすい。

- 題材・結論が実質同じ記事、同じ検索語を奪い合う記事がないか。あれば統合し、片方を301か削除する。
- 一般論だけで一次情報（独自集計・比較表・実践記録）が無い記事の割合を確認する。目安として半数を超えたら、新規追加より既存記事への一次情報追加を優先する。
- 薄い記事（本文が短い・出典が弱い）は加筆するか `noindex` にする。

## 2. 一次情報

- メディアごとに「SEADICE調べ」と言える独自の数字・整理が最低1つあるか。

## 3. 道具への導線

- 記事から関連アプリ・Webツールへの導線があるか（アプリがまだ無いメディアは対象外）。
- Webツールがある場合、`tool.md` のページの型を満たしているか。

## 4. 固有名で覚えられる状態

- 運営者情報（`/about/`）・免責・出典方針のページがそろっている。
- Organization の JSON-LD と `sameAs` が seadice.win と相互に参照し合い、表記が全メディアでそろっている。
- `llms.txt` に最新の記事索引が載り、seadice.win の `llms.txt` にもこのメディアが載っている。

## 5. 構造

- どこからもリンクされていない孤立ページが無い。
- カテゴリハブから3クリック以内に全ページへ届く。
- sitemap のURL数と実ページ数が一致する。

## 6. 鮮度

- 内容を見直した記事だけ `dateModified` を更新する（中身を変えずに日付だけ更新しない）。
- 統計・制度など古くなる数字を含む記事は、出典の年を確認して必要なら更新する。

## 7. 計測（外部スクリプトなし）

- Search Console で、インデックスされないページの割合と、表示回数ゼロが続くページを確認する。1・6の統合・noindex・加筆の判断材料にする。

## 進め方

- 3〜5は `python3` で全ページを横断して一覧化してから、問題のあるページだけ個別に見る（`base.md` のトークン節約と同じ）。
- 1の重複チェックは、`{slug}-posts.json` のタイトル・summary を並べて目視するところから始める。
