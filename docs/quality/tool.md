# 品質基準: Webツール（siteType: tool）

`base.md` に加えて適用する。計算・診断・チェックリストなど、読者が操作して結果を得るページ向け。

## 前提: 検索エンジンもAIもツールを操作しない

- Googlebot はページを表示するが、入力して結果を出すところまではしない。AI検索もツールを実行できない。
- 評価・引用されるのは**ツールの周りの文章**（何をするか・計算方法と根拠・入力例と結果）。入力欄とボタンだけのページは中身の薄いページになる。
- 一方で、AIは「その人の数字での計算」はできない。ここがAI時代にツールを置く理由になる。

## ページの型（上から順に）

1. h1 は検索されそうな言葉をそのまま使う（例: 「昼寝の最適な長さ 計算」）
2. ファーストビューにツール本体。JS はインラインで最小限、外部スクリプトなし
3. ツール直下に120字以内の結論（ツールを使わなくても分かる目安）
4. 計算方法・判定基準と、その根拠の出典
5. 入力例と結果の例を表で
6. FAQ（2問以上、1問目は `open`）
7. 継続して使う人向けに関連アプリへの導線

## やってはいけないこと

- **言い換え違いの似たツールを量産しない。** 「〇〇計算」「〇〇 計算方法」等を別ページにするのは入口だけを増やすページ（ドアウェイ）扱いになる。1テーマ1ページ。
- **結果ごとにURLを作ってインデックスさせない。** `?result=A` 等は `noindex` か、canonical を元ページに向ける。
- 診断結果を医療的・断定的な判断として示さない。

## 公開前チェック

1. ツールがJS無効でも、説明文・計算方法・例の表は読める
2. 結論文・計算方法・出典・例・FAQ がそろっている
3. 結果URLがインデックス対象になっていない
4. 同じテーマのツールが既に無い
5. スマホで入力欄・ボタンが指で操作しやすい（タップ領域・キーボード種別）
6. JSON-LD（`WebApplication` または `SoftwareApplication` + `BreadcrumbList`）がパースできる
