# SEADICE STUDY 設計書

無料の独学サイト群（siteType: course）のルールブック。新しい分野を足すとき・レッスンを書くとき・生成スクリプトを直すときは、各サイトの `{slug}-lesson.md` より先にこれを読む。品質の細目は `docs/quality/base.md` と `docs/quality/course.md`。食い違うときはこの文書を優先する。

## 0. 最上位の原則

**読みやすい・情報量が多すぎない・記憶に残る・ストレスがない。そして、使った人が「これは最高だ」と思えること。**

網羅性は目標にしない。全部を書くより、大事なことだけを確実に覚えて帰ってもらう。迷ったら「削る」を選ぶ。品質は「気をつける」ではなく、14章のチェックリストで毎回確かめる。

## 1. STUDYとは

「〇〇を無料で独学するならどこ？」の答えになる、1分野1サイトの学習サイト。

| | メディア | STUDY |
|---|---|---|
| 目的 | 検索から記事に来てもらう | AIに「独学するならここ」と名前を挙げてもらう |
| 更新 | 毎日1本（routine） | 完成させる。完成後は年1回の見直し |
| 評価 | 記事数・アクセス | 完成度・AIでの言及・学習者の満足 |

## 2. 想定する学習者

- その分野がまったく初めて。専門用語は1つも知らない前提で書く
- スマホで、通勤中・すきま時間に、1回5分。途中で中断されることがある
- 独学なので、わからなくても質問できる相手がいない
- 続かなかった経験がある。少しでも面倒だと離れる

「この人が5分で読み終えて、3つ覚えて、次も読みたくなるか」がすべての判断基準。

## 3. ストレスフリー設計

学ぶ人がイライラ・不安・面倒を感じる原因を、設計の段階でなくす。

### 始めるまで
- 登録・ログイン・メールアドレスの入力をさせない
- 広告・ポップアップ・Cookieバナー・通知の許可要求を出さない
- トップから1タップで第1レッスンを読み始められる
- 各レッスンに「約5分」の目安を出す。どれだけかかるか分からない不安をなくす

### 読んでいる間
- 1画面に詰め込まない。スクロールしても迷わない一本道の構成
- 読み込みが速い（JSなしで本文が出る・外部リクエストなし・レイアウトがずれない）
- 端末のダークモードに自動で合わせる。文字サイズはブラウザの拡大に追従する
- 専門用語は初出でその場で意味がわかる。別ページに飛ばないと読めない書き方をしない
- 戻るボタンが期待どおりに動く。勝手にページが変わらない

### 中断と再開
- 途中でやめても「続きから」すぐ戻れる（進み具合はブラウザに自動保存）
- 1レッスンが短いので、どこで中断しても区切りがよい
- 保存できない環境（プライベートブラウズ等）でも、本文と問題は普通に使える

### 間違えたとき
- 間違いを責めない。「惜しい」「ここがポイント」と、正解への道すじを示す解説にする
- 間違えた問題は自動で復習リストに入る。自分で記録する手間をかけない
- 制限時間を設けない（模擬試験だけは任意で時間を計れる）

### 続けるために
- 連続日数が途切れた・ノルマ未達などの「失う」演出をしない
- 順番を強制しない。どの章からでも読める（おすすめの順番は示す）
- 達成感は「章を読み終えた」「問題が解けるようになった」で出す。バッジやポイントは入れすぎない

## 4. 記憶に残すための型

学習科学で効果が確かめられている方法を、レッスンの型に組み込む。

| 方法 | レッスンでの形 |
|---|---|
| 少しずつ区切る（認知負荷を下げる） | 1レッスン1つの問い・約5分 |
| 先に問いを示す | 冒頭に問いを置き、読む前に予想してもらう |
| 思い出す練習（想起練習） | 読み終えたら、本文を見ずに答える確認問題 |
| 間隔をあけた復習 | 冒頭で前のレッスンを1問復習。暗記カードは間違えた語ほど早く出す |
| 言葉と図をセットにする | 1レッスンに図か表を1つ |
| 具体例 | 日常の場面の例を必ず1つ |
| 自分ごと化 | 「あなたの生活だと？」の問いかけを1つ |

### レッスンの並び（全サイト共通）

1. このレッスンの問い（1行）と、予想してもらう一言
2. 前のレッスンの復習1問（各章の最初のレッスンでは省いてよい）
3. 本文（3セクションまで）＋図か表を1つ
4. あなたの場合は？（問いかけ1つ）
5. 覚えるのはこの3つ
6. 確認問題3問（うち1問は日常の場面への応用）
7. 次のレッスンへ／出典（折りたたみ）

## 5. レッスンのデータ形式

講座JSON `media/{slug}-course.json` の `chapters[].lessons[]` に入れる。HTMLは手で書かない。

```json
{
  "id": "loss-aversion",
  "date": "2026-10-04", "modified": "2026-10-04",
  "title": "損失回避とは？なぜ1万円を失う痛みは、得る喜びより大きいのか",
  "short": "損失回避",
  "description": "損失回避とは、同じ金額でも得るより失うほうを強く感じる心の傾向です。…（120字以内・言い切り）",
  "question": "1万円をもらう喜びと、1万円を落とす悲しさ。どちらが大きいと思いますか？",
  "review": {"q": "…", "choices": ["…", "…", "…"], "a": 0, "exp": "…"},
  "sections": [
    {"h": "…", "answer": "1文の言い切り", "paras": ["…", "…"]}
  ],
  "figure": {"kind": "table", "caption": "…", "head": ["…"], "rows": [["…"]]},
  "apply": "最近、損をしたくなくて決められなかったことはありますか？",
  "keep": ["…", "…", "…"],
  "terms": [{"ja": "…", "en": "…", "def": "…"}],
  "quiz": [{"q": "…", "choices": ["…", "…", "…"], "a": 1, "exp": "…", "apply": true}],
  "sources": [{"text": "…", "url": "…"}]
}
```

- `figure.kind` は `table`（表）か `svg`（インラインSVG。`"svg"` キーに中身）か `swatches`（色見本。`[{"name","hex"}]`、色彩系のみ）
- 旧形式の `goals` / `summary` は使わない（`keep` に置き換え）。旧形式のレッスンも表示できるよう、エンジンは両方を読める
- `review` は前のレッスンの内容から作る（同じ問題の使い回しは不可）

## 6. 書き方の基準

### 分量（`--check` で自動検査する）

| 項目 | 基準 |
|---|---|
| 本文（paras の合計） | 600〜1000字 |
| セクション | 1〜3 |
| 1段落 | 3文まで |
| 1文 | 80字を超えない（目安60字） |
| keep（覚えるのはこの3つ） | ちょうど3 |
| terms（新しい用語） | 3語まで |
| quiz | 3問、うち `apply: true` が1問以上 |
| 太字 | 1セクション1か所まで |
| sources | 2件以上 |
| title / description | 40字 / 120字まで |

### 文体

- です・ます調。読者に話しかける（「〜ですよね」「考えてみましょう」は使ってよい）
- 専門用語は、先に平易な言葉で言い、後から用語名を示す（例:「失う痛みを強く感じる傾向。これを損失回避と呼びます」）
- 各セクションの最初の1文で答えを言い切る。前置きを書かない
- 「〜と言われています」「諸説あります」で逃げない。研究で確かでないことは「まだはっきりしていません」と正直に書く
- 「後の章で学ぶ」内容は先取りせず、リンクだけ張る

### 良い例と悪い例

同じ「損失回避」の冒頭。

悪い例（情報を詰め込み、答えが遅い）:
> 行動経済学は、1970年代にダニエル・カーネマンとエイモス・トベルスキーが提唱したプロスペクト理論を出発点とし、伝統的経済学が前提としてきたホモ・エコノミカスという合理的経済人の仮定に疑問を投げかけてきました。その中心的な概念の一つが損失回避であり、参照点依存性や感応度逓減とともに価値関数の形状を特徴づけ……

良い例（問い→言い切り→日常の例、用語は後から）:
> 1万円をもらう喜びと、1万円を落とす悲しさ。多くの人は、落とす悲しさのほうが大きいと感じます。
> 同じ金額でも、得るより失うほうを強く感じる。この心の傾向を「損失回避」と呼びます。

## 7. 正確さと信頼

- 数値・年・定義・法律名は、開いた出典の本文で1件ずつ確認する。確認できないものは書かない
- 出典は公的機関・原典・学会・大学など一次情報。まとめサイト・個人ブログ・検索スニペットだけを根拠にしない
- 再現性が揺らいでいる研究は、断定せずその旨を書く
- 統計は年と時点を本文に書く
- 公式テキスト・過去問・市販書の文章や問題を写さない・言い換えない。確認問題はすべてオリジナル
- 誤りの報告を受けたら直し、`modified` を更新する。出典と検証の方法のページに、訂正の方針を書く
- AI（Claude）が調べて書いていることを about に正直に書く

## 8. 学習機能（共通エンジンに実装し、全サイトで共有する）

利用者のデータはブラウザ内（localStorage）だけに保存し、読み書きはすべて try/catch で包む。

| 機能 | 内容 | 優先 |
|---|---|---|
| 進み具合 | 読み終えたレッスンにチェック。「続きから」読める | 1 |
| 間違えた問題の復習 | 間違えた確認問題だけを集めて解き直す | 1 |
| 暗記カード | 用語辞典をカード化。間違えた語ほど早く出す | 1 |
| どこから始めるか診断 | 10問で、読み始める章を提案する | 2 |
| 学習プラン（資格型） | 試験日と1日の時間から、章の割り振りを出す | 2 |
| 1枚まとめ | 章ごとの「覚えるのはこの3つ」を1ページに集める | 2 |

### 分野ごとの看板ツール（1サイト1つ）

読むだけでなく「試して確かめる」体験で差別化する。ツールのページにも説明文と出典を付ける。

| サイト | 看板ツール |
|---|---|
| 心理学 | 有名な実験の体験（ストループ効果・系列位置効果など） |
| 貿易実務 | インコタームズの費用・危険の分担シミュレーター |
| 心理カウンセリング | 傾聴の応答練習、資格へのルート診断 |
| 犯罪学 | 犯罪白書のデータで推移を見るグラフ |
| 行動経済学 | 自分のバイアス測定（研究の平均と比べる） |
| 色彩検定 | 配色シミュレーター |
| ボディランゲージ | 俗説か研究か判定クイズ |

よく使われたツールは、iOSアプリ化の候補にする。

## 9. やらないこと

- 網羅を目指す・長い前置き・歴史の羅列から始める
- 1レッスンに4つ以上の「覚えること」・4語以上の新しい用語
- 登録・ログイン・広告・ポップアップ・外部スクリプト・外部フォント
- 連続日数の途切れを責めるなど、失う演出・焦らせる演出
- AIチャット欄の設置（費用と誤答のリスク。質問への答えは本文と用語辞典で用意する）
- 公式・公認と誤解される表現、民間資格や有料講座の宣伝
- 診断・治療・法律判断など、個別の専門的な助言
- 絵文字

## 10. サイトの型と共通ページ

| 型 | 例 | 追加で必須のもの |
|---|---|---|
| 学問型 | 心理学・犯罪学・行動経済学・ボディランゲージ | 学び方ガイド |
| 資格型 | 貿易実務・色彩検定 | 章末テスト・模擬試験・学習プラン |
| 職業型 | 心理カウンセリング | なり方と資格の正確な比較 |

全サイト共通: トップ／講座／レッスン／章末テスト／用語辞典／学び方ガイド（他の無料教材の公平な比較と学ぶ順番）／about／出典と検証の方法／免責

資格型は、試験の運営団体とは無関係であることを about と免責に書く。

## 11. 名前とブランド

- サイト名は「ゼロから学ぶ〇〇」（〇〇は本人が検索する平易な言葉。学問名は説明文に入れる）。心理学サイト（shinri）も2026-10-05に「日常の心理学」から改名済み
- 各サイトは分野名のサブドメインで独立させる（例: hanzaigaku.seadice.win）
- seadice.win/study/ に全講座の一覧（ハブ）を置き、ホームページの Study 枠からつなぐ
- 各サイトのフッターに「SEADICE STUDYの他の講座」を置く

## 12. 分野の選定基準（5つすべて満たす）

SEADICEは社会問題を解決するための情報（サイト・アプリなど）を無料で届ける団体。STUDYもその一部なので、**1を最優先**で判断する。学問として面白い・資格として人気がある、だけでは選ばない（2026-10-05〜）。

1. 社会問題の解決につながる。知っていれば被害・困窮・孤立を防げる、または必要な支援や制度にたどり着ける分野である（例: 犯罪と被害者支援、社会保障制度、労働者の権利、消費者トラブル、防災、依存症、メンタルヘルス）
2. 「独学 おすすめ」「無料で学べる」とAIに聞かれる分野である
3. 無料で体系的に学べる日本語サイトが手薄（大手が強い分野は避ける）
4. 公的機関・原典などの一次情報で書ける
5. SEADICEのメディア・アプリとつながる

医療・お金・法律（YMYL）に深く入る分野は、執筆と監査を分ける体制がある場合のみ扱う。

## 13. 運用と計測

- 同時に作るのは2サイトまで。1つを公開条件まで仕上げてから次へ
- 公開条件: 全章の構成が決まっている・第1〜3章が書けている・用語30語以上・学習機能（優先1）が動く
- レッスンは手元で書く（一次情報を開いて確かめるため。クラウドの自動実行は使わない）
- 完成後は年1回、制度改正・新しい研究を反映する
- 計測: サイトごとに質問を3つ決め、**着手前に**一度、以後は月1回、ChatGPT・Perplexity・Google AI Overview で名前が出るかを記録する。あわせて Search Console と匿名フィードバックを見る
- メディアの記事 → STUDYのレッスン、STUDY → 演習アプリ、の順で相互にリンクする

## 14. 品質チェックリスト（漏れなく確かめる）

### A. 自動（`--check` が落ちたら公開しない）
- 6章の分量基準（字数・セクション・段落・文の長さ・keep・terms・quiz・太字・sources・title/description）
- 必須キー（question / sections / keep / quiz / sources）がある。旧形式は警告
- id の重複がない。quiz の正解番号が選択肢の範囲内
- 用語辞典の def が「〇〇とは、」で始まる
- 生成後: 内部リンク切れがない・h1が各ページ1つ・JSON-LD がパースできる・他分野の文言が残っていない

### B. 書き手の自己検査（レッスンごと）
- [ ] 全出典URLを開き直し、数値・年・定義が出典に書かれていることを照合した
- [ ] 確認問題の正解が本文と一致し、不正解の選択肢が明確に誤り
- [ ] 本文を見ずに「覚えるのはこの3つ」が言える内容になっている
- [ ] 図か表が、本文の理解を本当に助けている（飾りではない）
- [ ] 既存レッスンと内容が重複していない
- [ ] 9章の「やらないこと」に当たる箇所がない

### C. 読者目線の確認（章ごと、公開前）
- [ ] スマホで1レッスンを通して読み、5分以内に終わった
- [ ] 読み終えて、見ずに3つ言えた
- [ ] 次のレッスンを読みたくなった
- [ ] 3章のストレスフリー設計に引っかかる箇所がない（迷う・待たされる・責められる・面倒）

### D. サイト単位（公開前・年1回）
- [ ] 10章の共通ページがすべてある
- [ ] about・免責・出典と検証の方法が最新
- [ ] 着手前と比べ、AIでの言及を記録した

## 16. エンジン

各サイトの `{slug}_pages.py`（boueki_pages.py の複製）は、共通エンジン `media/study.py` 1本に統合する。分野ごとの違い（文言・配色・看板ツール）は `media/{slug}.json` に持たせる。デザインや学習機能の修正は study.py の1か所で行い、全サイトに反映する。
