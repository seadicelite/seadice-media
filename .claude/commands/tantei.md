# デジタル探偵 の記事ルール

基本は `.claude/commands/research.md` の「読者」「鉄則（信頼性）」「手順」に従う。テンプレートは `.claude/commands/tantei-template.html`。以下はデジタル探偵固有の追加・上書きルール。

## 立ち位置（最重要）

**AI時代の見えない問題を解剖し、読者が「自分で確かめられる」ようにする。** 一般的な注意喚起（「怪しいリンクは開かない」）で終わらせない。どの記事も、読者が自分のスマホやパソコンで実際に手を動かせる「探偵の手順」が中心。

**記事の軸は「手口の解剖 → 自分で確かめる手順」（2026-10-03確定）。**
- 01 で、手口がどう作られ、なぜだまされるのかを作り手の目線で解き明かす（実行できる手順の粒度にはしない）。
- 03「探偵の手順」は最低3ステップ。各ステップは、OSの標準機能・公式ヘルプ・公的機関や非営利団体の無料の確認手段に基づくもので、**公式ヘルプのページを開いて、その手順が現在も有効であることを確認できたものだけ** を書く。確認したページは出典に入れる。
- 04 で、確かめた結果「怪しかった」「被害にあった」ときにすることと相談窓口を書く。

**調査ログで「調べたこと」を見せる（AIの量産記事との差別化の核）。** h1直下の `.log` に、この記事のために実際に開いて確認した資料を3〜6件、「何を確認したか」を1行ずつ書く。**実行していない確認・実験を書かない**（「実際に偽サイトを作ってみた」「電話をかけてみた」等は書かない。AIが実際にしたのは資料・公式ヘルプ・公開データの確認であり、それだけを書く）。日付は確認した日。

**扱うのは自分の身を守る確かめ方だけ。** 「自分の写真から何が読み取れるか」はよいが、「他人の写真から住所を特定する方法」は書かない。逆検索などの手段を紹介するときも、目的は自分に届いたもの・自分の情報の確認に限定して書く。

**何も売らない。** セキュリティソフト・有料サービス・書籍などの商品名やリンク、アフィリエイト、購入の勧めを一切書かない。確かめ方で名前を出してよいのは、OSの標準機能（iPhoneの写真の情報表示など）、主要な検索サービスの無料機能、公的機関・非営利団体の確認手段（警察庁・IPA・フィッシング対策協議会・国民生活センター、Have I Been Pwned 等）に限る。

**Before→After** は「これ本物？と不安なだけの自分 → 自分で確かめて判断できる自分」。

## 書いてはいけないこと（1つでも該当したら記事を破棄）

- 他人の身元・住所・アカウントを調べる方法、他人のアカウントへのアクセス、不正アクセス、セキュリティの回避方法。
- 詐欺・なりすまし・ディープフェイクを実行できる粒度の手順（使うツール名、作り方の手順など）。
- 商品名・有料サービス名、購入リンク、アフィリエイトリンク。
- 恐怖を煽る表現（「あなたの情報はすでに漏れている」等）、被害者を責める表現（「だまされる方が悪い」等）。
- 実行していない検証・実験を、したかのように書くこと。
- 法的な判断の断定（「これは違法なので訴えられます」等）。法律に触れる場合は一般的な情報と相談先までにする。
- 実在の個人・企業を、確認されていないのに詐欺と結びつける記述（公的機関が名前を出して注意喚起している場合は、その出典つきでのみ可）。
- 開発側の事情（課金・価格）。絵文字。

## 相談窓口（04で該当するものを1〜2個添える）

- お金をだまし取られた・脅されている: 警察相談専用電話 #9110、各都道府県警察のサイバー犯罪相談窓口。身の危険は110番
- 通販・契約のトラブル: 消費者ホットライン 188
- ネット上の誹謗中傷・なりすまし・画像の無断掲載: 違法・有害情報相談センター（総務省支援）、法務省の人権相談
- 確認したURLの窓口名は、公式ページで現在の名称を確かめてから書く

## 出典

情報セキュリティ・心理学・メディア研究などの査読論文、警察庁・総務省・IPA・国民生活センター・フィッシング対策協議会・NISCなど公的機関の資料、OSやサービスの公式ヘルプに限る。セキュリティ製品の販売会社による調査レポートは出典にしない。統計を使うときは何年の数値か、誰が対象かを必ず書く。数字は条件まで原典と一致させる（`kokoro.md`「数字は条件まで原典と一致させる」と同じ基準）。公式ヘルプの手順は画面名・メニュー名まで原典どおりに書く。

## テーマの選び方

読者が実際に検索する言葉から作る（「〇〇 本物 確認」「〇〇 詐欺 見分け方」「〇〇 漏れてる 確認」など）。警察庁・国民生活センター・フィッシング対策協議会の最新の注意喚起から、今まさに増えている手口を優先する。BOHAN（bohan.seadice.win）の「AI時代の防犯」カテゴリと題材が近い場合は、BOHANが「犯罪者の目線と備え」、デジタル探偵が「自分で確かめる手順」と役割を分け、同じ結論の記事を作らない。

## 記事の構成（設定の types は guide のみ）

テンプレートの見出しをそのまま使う。01 手口の解剖 / 02 研究とデータでわかっていること / 03 探偵の手順 / 04 怪しかったとき・被害にあったときにすること / 05 よくある質問 / 出典。
- h1直下に `.log`（調査ログ）。
- 02の結論文の直後に `.stats`（核心の数字2〜4個、対象と年を添える）を置く。
- 03の各ステップに「所要 ◯分」と、iPhone/Android/パソコンなど対象を添える。
- タイトルの語尾を固定しない（「確かめる手順」ばかりにしない。同じ語尾は直近10本中3本まで）。
- 関連アプリ欄・APP IDEA は入れない。

## 投稿データ（media.md 手順5）

`media/tantei-posts.json` の先頭に `{"slug","category"(設定のcategoriesのname),"type":"guide","date","title","summary"}` を追加する。

## 写真のルール

`ledger.md` の写真のルールと同じ（`python3 media/photo.py tantei {記事slug} "<検索語>"`、候補なしは検索語を変えて2〜3回まで再検索、使い回しは最終手段）。人の顔・画面に個人情報が写った写真は使わない。虫眼鏡・スマホ・キーボード・地図・鍵など、調べる・確かめる印象の写真に寄せる。
