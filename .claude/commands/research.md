# /research — 悩み／科学 → 研究の記事

`$ARGUMENTS` について、公開された研究を調べ、`sites/research/{スラッグ}/index.html` を作る。確認不要で最後まで実行し、記事URLを報告する。

**2026-09-23〜、記事末の「この研究から考えた、こんなアプリ」（APP IDEA）セクションは廃止した。** 悩み→科学→研究の解説に集中し、アプリ提案は記事に含めない（既存記事からも削除済み）。

## 入口は2種類（どちらも同じ記事の型に着地する）

| 入口 | 例 | 導入（読者の「入り口」） | 01の見出し |
|---|---|---|---|
| **悩みから** | 夜更かしをやめられない | 悩みへの共感・問いかけ | 悩みの正体を、やさしい言葉で |
| **科学・研究から** | 「昼寝は何分が最適か」「習慣が身につく日数の研究」 | 「へえ」と思う発見・意外な事実・問い | この研究でわかった、意外なこと |

- `$ARGUMENTS` がどちらか迷うときは、読者が検索しそうな側（悩み）を優先し、科学トピックは「〇〇の研究」を「〇〇したい人へ」の言葉に言い換えられないか先に考える。
- 面白い研究を紹介する記事でも、出典検証の鉄則は同じ。

## 読者（最優先）

読者は、その悩みを実際に抱えて検索してきた**一般のユーザー本人**。研究者でも開発者でもない。**読みやすさと、読んで楽しいことを何よりも優先する。** 記事は「自分の悩みが科学的に説明され、今日から試せることがわかる」ものにする。

- 専門用語は使わない。使うなら初出で平易に言い換える（例:「概日リズム（体内時計）」）。
- 冒頭は読者の悩みへの共感か問いかけから入る（例:「わかっているのに夜更かしをやめられないのは、意志が弱いからではありません」）。責めない、不安を煽らない。
- 論文の説明は「何がわかったか」を先に、研究デザインの詳細は短く。読者が知りたいのは結論と「自分は何をすればいいか」。
- 「今日からできる実践」は、読んですぐ試せる小さな行動にする（所要時間や回数を添える）。
- 開発側の事情（課金、価格、内部の意図、開発スケジュール）は記事に書かない。
- 1文を短く、段落を細かく、見出しは読者の言葉で。難しい話ほど例えや具体例を添える。

## 鉄則（信頼性）

- **確認できた出典だけを書く。** 論文・数値は WebFetch / WebSearch で実在と内容を確認してから使う。確認できなかった論文・数値・引用は書かない。記憶や推測で補完しない。
- SEADICEは一次研究をしていない。「私たちの研究で」「実験の結果」などの表現は禁止。「〇〇ら（年）の研究では」と第三者の研究として書く。
- 「必ず治る」「〜すべき」等の断定・医療行為に当たる助言は避ける。心身の不調が深刻な場合は専門家への相談を促す一文を入れてよい（ただしひきこもり系は外部機関誘導を入れない方針）。
- 効果を誇張しない。研究の対象（人数・年齢・条件）と限界を1〜2文で添える。
- 絵文字禁止。

## 手順

1. **入口の判定と絞り込み**: 上の2種類のどちらかを判定する。`$ARGUMENTS` が空なら、`ls sites/research/` で既存記事を見て、被らない悩みを1つ選ぶ。広いジャンルでなく「誰の・どんな状況の・どんな悩み」まで狭め、Before→After（〇〇な自分→△△な自分）を一言で言える形にする。専門用語でなく本人が検索する平易な言葉にする。
2. **重複確認**: `ls sites/research/` で同テーマがないか確認。あれば別の切り口にするか中止して報告。
3. **調査**: WebSearch で査読論文・レビュー論文・メタ分析・公的機関（厚労省・WHO・NIH等）を複数探す。日本語と英語の両方で検索する。目安は3〜6件。
4. **検証**: 採用する各出典を WebFetch で開き、著者・年・雑誌名・対象・結果を確認する。開けない・内容が合わないものは不採用。
5. **執筆**: `.claude/commands/research-template.html` を元に `sites/research/{スラッグ}/index.html` を作る。
   - スラッグは英小文字とハイフン。
   - h1直後に結論1〜2文。各h2直下に120字以内の結論かリスト。
   - 構成（テンプレートのとおり）: 導入 / 3行でわかる / 01 悩みの正体 / 02 科学的にわかっていること（研究カード） / 03 今日からできる小さな一歩（ステップカード） / 04 続けるためのコツ / 05 よくある質問 / 出典。
   - デザインはテンプレートのクラス（`.summary` `.study` `.step` `details`）をそのまま使い、読みやすさを崩さない。JSは使わない。
   - 具体的な数値・固有名詞を最低3箇所（出典で確認済みのもののみ）。
   - 本文800〜1500字。表かリストを各h2に1つ。
   - 出典は末尾に番号付きで、著者・年・タイトル・雑誌・URLを載せる。JSON-LD の `citation` にもURLを入れる。
   - 日付は今日（`date +%F`）。datePublished / dateModified。
6. **配線・公開**: 一覧・sitemapの再生成、写真、公開（git push）は `.claude/commands/media.md` の手順に従う（一覧やsitemapを手で編集しない）。
