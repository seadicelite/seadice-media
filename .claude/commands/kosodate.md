# AI時代の子育て の記事ルール

基本は `.claude/commands/research.md` の「読者」「鉄則（信頼性）」「手順」に従う。テンプレートは `.claude/commands/kosodate-template.html`。以下はAI時代の子育て固有の追加・上書きルール。

## 立ち位置（最重要）

**親の疑問に、研究データから結論を先に答える。** 「子どもにAIは何歳から？」のような親が実際に検索する疑問をタイトルにし、冒頭で結論を言い切る（言い切れない場合は「研究ではまだ結論が出ていない」と言い切る）。

**わかっていることと、わかっていないことを分ける。** 子どもとAIの研究はまだ新しい分野。古いスクリーンタイム研究や大人対象の研究を、子どもとAIにそのまま当てはめない。当てはめる場合は「大人を対象にした研究では」「スマホ・動画の研究では」と対象を必ず書く。03「まだわかっていないこと」は省略しない。

**わかっている度（★3段階）を必ず付ける。**
- ★★★: 複数の研究・メタ分析・公的機関の指針で結果がそろっている
- ★★☆: 研究はあるが、数が少ない・条件が限られる
- ★☆☆: 研究がほとんどない・結果が分かれている・間接的な研究からの推測

**何も売らない。** 教材・アプリ・通信教育・知育玩具などの商品名やリンク、アフィリエイト、購入の勧めを一切書かない。対策はお金をかけずに家庭でできる行動・ルール・声かけを中心にする。

**Before→After** は「何が正しいのか分からず不安な親 → 根拠をもとに、わが家のやり方を決められる親」。

## テーマの選び方（検索される悩みから作る、2026-10-02〜）

テーマは「親が実際に検索している悩み」から選ぶ。研究ありきでテーマを決めない。

- **悩みを集める**: トピックを選ぶ前・キューを補充するときに、WebSearchで親の実際の悩みを調べる。見る場所の例: Yahoo!知恵袋・発言小町などのQ&A、検索サジェスト（「子ども スマホ 〜」「小学生 AI 〜」等の続き）、こども家庭庁・文部科学省・総務省・ベネッセ教育総合研究所などの保護者調査。よくある悩み・何度も繰り返し聞かれている悩みを優先する。
- **ロングテールからスモールテールまで混ぜる**: 「子ども スマホ 何時間」のような検索数の多い短いキーワードだけでなく、「小学生 YouTube やめられない 対策」「3歳 動画 見ないと泣く」のような具体的で長いキーワードも積極的に記事にする。長いキーワードは競合が少なく、悩みが具体的なので結論を言い切りやすい。
- **タイトルは検索語に寄せる**: 親が検索窓に打ちそうな言葉をそのままタイトルの前半に入れる（例:「子どもがYouTubeをやめられない。研究でわかった声かけと…」）。専門用語をタイトルに入れない。
- **テーマはAI時代に限らない**: AI・スマホ・ネットに関係する悩みを中心にしつつ、学び・心・親子関係など設定のカテゴリに入る子育ての悩み全般を扱ってよい。
- **研究で答えられるものだけ**: 悩みに対して、確認できる研究や公的なデータが見つからないテーマは捨てて次へ（鉄則どおり）。
- **キューは入れ替えてよい**: `topicQueue` の先頭より、検索で見つけた悩みの方が検索需要が明らかに大きい場合は、そちらを先に書いてよい。キューを補充するときは、ロングテール（具体的な悩み）を半分以上にする。
- **重複を避ける**: 同じ悩みを言い換えただけの記事を作らない。近いテーマの既存記事がある場合は、年齢・場面を変えるなど切り口をはっきり分ける。

## 50本時点の抜き取りで見つかった誤り（2026-10-02 追加、再発させない）

- **英語の専門用語を訳すときは原文の意味を確かめる**: 「non-intelligent tutoring systems」を「人間でない〜」と誤訳した例あり（正しくは「AIを使わない従来型の〜」）。比較の相手（何と比べたか）は特に注意する。
- **レビュー論文が紹介している先行研究の数字は、その旨を書く**: 「この論文の調査では」ではなく「この論文が紹介している先行研究では」。原典にない「すべて」「〜が原因で」を足さない。
- **範囲の数字は区切りを原典どおりに**: 「6〜10分」の割合を「6〜10分以上」と書いた例あり。表の数字は行・列の意味を確かめてから使う。
- **タイトルの語尾を固定しない**: 「研究でわかっていること」で終わるタイトルが50本中36本あった。悩みの言葉で始め、語尾は「〜の目安」「〜のコツ」「〜は本当？」など内容に合わせて変える（同じ語尾は直近10本中3本まで）。

## 書いてはいけないこと（1つでも該当したら記事を破棄）

- 商品名・サービス名・アプリ名、購入リンク、アフィリエイトリンク。
- 親を責める表現（「スマホを与える親は〜」等）、不安を煽る表現（「脳が壊れる」等）。
- 研究の過大な一般化（相関を因果のように書く、大人の研究を子どもの結論として書く）。相関研究は「関連があった」と書く。
- 発達障害・病気などの診断や治療の助言。発達・睡眠・心の様子で気になる場合は「かかりつけの小児科や自治体の子育て相談窓口」を1つ添える。
- 特定の家庭の形（ひとり親・共働き等）を問題視する記述。
- 開発側の事情（課金・価格）。絵文字。

## 出典

**数字は条件まで原典と一致させる（2026-10-02 追加）。** 「1日何時間以上で」「何歳の」「どの分析で」といった条件も、原典の文と1つずつ照合する（条件を取り違えた実例あり: 1時間以上の結果を2時間以上と書いた）。要旨にない数字は、本文（Europe PMC の fullTextXML など）で確認できたものだけを使う。大人や大学生が対象の研究は、ラベルにも「18歳以上」「大人」と明記し、子どもの結果のように見せない。

発達心理学・教育学・小児医学・メディア研究の査読論文、メタ分析・システマティックレビュー（Cochrane 等）、WHO・米国小児科学会（AAP）・OECD・ユネスコ・文部科学省・こども家庭庁・総務省などの公的なデータと指針に限る。教材・アプリ事業者や通信教育会社の調査は出典にしない。統計を使うときは何年の数値か、何歳の子どもが対象かを必ず書く。

## 記事の構成（設定の types は guide のみ）

テンプレートの見出しをそのまま使う。01 結論から言うと / 02 研究とデータでわかっていること / 03 まだわかっていないこと / 04 家庭で今日からできること / 05 よくある質問 / 出典。
- h1直下の `.evidence` に、わかっている度と「研究◯本・公的指針◯件を整理」を書く（本数は出典リストと一致させる）。
- 02の結論文の直後に `.stats`（核心の数字2〜4個、年齢と年を添える）を置く。
- 04は最低3つ、家庭でお金をかけずにできる行動・ルール・声かけにする。対象年齢が分かれる場合は年齢を書く。
- 関連アプリ欄・APP IDEA は入れない（アプリはメディアが育ってから作る方針）。

## 投稿データ（media.md 手順5）

`media/kosodate-posts.json` の先頭に `{"slug","category"(設定のcategoriesのname),"type":"guide","date","title","summary"}` を追加する。

## 公開

`publish` が `draft` の間は、media.md の draft 手順（ブランチ＋PR）に従い、main へは直接 push しない。

## 写真のルール

`ledger.md` の写真のルールと同じ（`python3 media/photo.py kosodate {記事slug} "<検索語>"`、候補なしは検索語を変えて2〜3回まで再検索、使い回しは最終手段）。加えて、子どもの顔がはっきり写った写真は使わない（物・場所・手元の写真に寄せる。例: "tablet desk", "children's books", "crayons table"）。

## 出典照合のチェック項目（書き手・点検役の両方。2026-10-05〜）

記事を書くとき・点検するときは、`docs/quality/article.md` の「出典の正確さ」の8項目（結論が出典と逆、出典にない数字、別の論文・ページへのリンク、別の研究・地域・対象の結果の混入、プレスリリースの解釈を結果として断定、査読でない資料を研究として扱う、平均/中央値・確率/オッズ比・相関/因果の取り違え、出典にない強い言葉）を1つずつ確認する。数字の確認だけで「照合済み」にしない（2026-10-04のサンプル点検で、照合済みの記事に結論が逆の誤りが残っていた）。
