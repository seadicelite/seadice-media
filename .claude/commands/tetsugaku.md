# 哲学 の記事ルール

基本は `.claude/commands/research.md` の「鉄則（信頼性）」と文章の質チェック（PREP法・h2直下の結論・具体例）に従う。テンプレートは `.claude/commands/tetsugaku-template.html`。以下は 哲学 固有の上書きルール。

## 入口（research.md と違う点）

読者は「悩み」ではなく「名前は知っているが説明できない哲学者・概念・学派」を検索してくる。入口は常に**人物名・概念名・学派名**（例: ソクラテス、実存主義、トロッコ問題）。悩み解決の Before→After 型には寄せない。

- `$ARGUMENTS` が空なら `topicQueue` の先頭、または `ls sites/tetsugaku/` と被らない哲学者・概念を選ぶ。
- 導入は「へえ」と思わせる意外な事実・誤解されがちな点・問いかけから入る（悩みへの共感ではない）。
- 「今日からできる小さな一歩」ではなく「今の生活・現代社会での意味」を書く（実践ステップの押し付けにしない）。

## 読者

学校や本で名前だけ聞いたことがある人物・概念を、検索して10分で理解したい一般の人（哲学専攻ではない）。**「知ってるつもり」を「他人に説明できる」に変える**ことがゴール。

- 専門用語（実存、弁証法、アプリオリ 等）は初出で必ず平易に言い換える。
- 「〜と言われている」で逃げず、原典が実際に何を主張したかを明確に書く。ただし解釈が分かれる論点は「〜という解釈がある」と幅を示す。
- 特定の思想・宗教・政治的立場が正しい／間違っているという断定はしない。史実・原典の内容の説明と、現代的な意味づけを区別する。

## 出典

原典（可能なら邦訳・英訳の版を明記）、研究書、大学出版の哲学事典（**スタンフォード哲学百科事典 plato.stanford.edu**、Internet Encyclopedia of Philosophy 等）、大学の講義資料に限る。二次的なまとめサイト・SNS由来の要約だけを根拠にしない。原典の直接引用を使う場合は、訳の出典（訳者・出版社）も明記する。

## 記事の種類ごとの構成（設定の types は guide のみ）

テンプレートの見出しの並び（番号の横の小さいラベルとして残し、大きい見出しはその記事の問いを質問の形で書く。docs/quality/base.md「見出しは読者の質問にする」）: 01 これは何か（人物・概念の正体）/ 02 どんな時代・文脈で生まれたのか / 03 中心の思想を、生活の言葉で / 04 今の生活・現代社会での意味 / 05 関連する哲学者・概念 / 06 よくある質問 / 出典。

- 05「関連する哲学者・概念」は既存記事があれば `/{スラッグ}/` にリンクする。まだ無ければこのブロック自体を省略してよい（存在しないリンクを書かない）。
- **「この人物・概念から考えた、こんなアプリ」セクション（APP IDEA）は入れない。** RESEARCH/しぐさと本音と違い、哲学は百科事典として読まれるメディアなので、記事末に毎回アプリ案を挟むと編集記事としての説得力を損なう（2026-09-23、全既存記事から削除済み）。

## 投稿データ（media.md 手順5）

`media/tetsugaku-posts.json` の先頭に `{"slug","category"(設定のcategoriesのname),"type":"guide","date","title","summary"}` を追加する。

## 目的別ガイド・用語集・照合済みへの追加（2026-10-06〜）

読者は「名前を確認したい」「生き方に迷った」「テスト前」など目的を持って来る。新しい記事は一覧に足すだけでなく、目的の入口からも辿れるようにする。

- `media/tetsugaku-guides.json`: 記事が当てはまるガイド（first-step / exam / how-to-live / right-and-wrong / ai-mind-science / work-society）の `slugs` に追加する。当てはまらなければ追加しない。
- `media/tetsugaku-glossary.json`: 記事の中心概念が未収録なら1語追加する（`id`,`term`,`en`,`def`,`slugs`）。`def` は記事のFAQの答えと同じ内容にし、記事にない主張を足さない。五十音順の位置に入れる。
- `media/tetsugaku-audited.json`: 公開前の出典照合（docs/quality/article.md「出典の正確さ」）を済ませたら `{"slug","date"}` を追加する。照合していない記事は追加しない。
- `media/tetsugaku.json` の `apps`: 記事が `theme` に書かれた哲学者本人（哲人フレンドに登場する人物）の記事なら、`articles` に slug を追加する。アプリ用ページとアプリカードは build.py が自動で作る。
- 写真を `photo.py` で取るときは `--alt="写っている物を日本語で短く"` を付ける（英語の説明文のまま公開しない）。

## 写真のルール（カテゴリ単位のプール運用。umbra と同じ方式）

- 画像は記事ごとに探さない。`media/tetsugaku-images.json` にカテゴリ単位（`c-ancient`/`c-modern`/`c-existential`/`c-ethics`/`c-eastern`/`c-contemporary`）で1枚ずつ登録し、`sites/tetsugaku/img/` に保存したプールを使い回す。
- 人物の肖像画・彫像（パブリックドメインのもの。Wikimedia Commons）を優先する。実在の哲学者の写実的な肖像がある場合はそれを、無い時代・概念記事は建築・書物・自然物などの象徴的な写真にする。
- 新しいカテゴリでプールに画像が無い場合だけ `python3 media/photo.py tetsugaku {記事slug} "<検索語>"` を1回実行する。候補なし・失敗時は写真なしで続行する。
